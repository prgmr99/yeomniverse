## 0. 요약 (TL;DR)

효도티어는 콘텐츠 완성도는 이미 높지만, **결과가 서버에 남지 않아 "사회적 증거"를 만들 수 없고**, **공유 루프가 1홉에서 끊기며**, **모든 카피가 어버이날(5월)에 고정**되어 있다. 지금 트래픽이 조금씩 오르는 것은 유형별 롱테일 SEO가 누적된 결과로 보이며, 여기에 **추석이라는 연 2회뿐인 "가족 시즌"** 을 얹으면 계단식 점프를 노릴 수 있다.

이번 스프린트는 3개 축을 동시에 건드린다.

| 축 | 한 줄 전략 | 대표 기능 |
|---|---|---|
| **A. 루프 (K-factor)** | 결과를 "혼자 보는 성적표"에서 "상대와 비교하는 대결"로 전환 | 익명 집계 기반 **상위 X%**, **맞대결 부메랑 루프** |
| **B. 유입 (SEO)** | 어버이날 단일 시즌 → 추석/명절 키워드 축 추가 | 명절 블로그 4편, 3교시 결과 유형 랜딩 9종 |
| **C. 체류/재방문 (콘텐츠)** | 기존 사용자에게 "새로 풀 것"을 준다 | **3교시 명절 생존력 시험** |

**컷 라인**: 관계 확장(배우자/형제/조부모편)은 추석 이후로 미룬다. 3주 안에 백엔드 + 신규 퀴즈 + 카드 이미지를 모두 넣으면서 관계 확장까지 하는 건 불가능하다.

### 1.2 현재 계측되는 이벤트

`quiz_start` / `quiz_complete` / `share_clicked` / `shared_link_opened` / `retake_from_shared` / `parent_quiz_cta`

**측정 공백**: 공유 1건이 몇 명을 데려오는지(증폭률), 그리고 그 사람이 **다시 공유하는지(2홉)** 를 알 수 없다. 공유 링크에 식별자가 없어서 홉 추적이 불가능하다.

### 1.3 구조적 한계 3가지

**① 서버 저장이 없다**
결과가 URL 쿼리스트링으로만 전달된다. "전체 응시자 중 상위 3%", "오늘 12,431명 응시", "가장 흔한 유형은 K-장녀" 같은 **사회적 증거를 만들 수 없다**. 심리테스트 바이럴에서 스크린샷을 유발하는 건 유형 그 자체보다 **"상위 X%"라는 비교 가능한 숫자**다.

**② 바이럴 루프가 1홉에서 끊긴다**
현재 루프: `A 응시 → 공유 → B 열람 → B 응시 → (끝)`
B가 응시를 마쳐도 **A에게 되돌아가는 동선이 없다**. 부모편에만 비교 화면(`?parent=`)이 있고, 자녀↔자녀(친구·형제) 대결 프레임이 없다. 2홉이 안 생기면 K < 1로 수렴하며 바이럴이 지수 성장하지 못한다.

**③ 어버이날 시즌에 고정되어 있다**
`app/layout.tsx`의 title/description/keywords, OG 문구, 랜딩 배지(`getParentsDayBadge`)가 모두 5월 기준이다. 8월 방문자에게는 "철 지난 서비스"로 읽히고, 추석 검색 키워드는 하나도 잡지 못한다.

**④ (기술부채) 퀴즈 엔진이 복붙 구조다**
`useQuizStore`/`useParentQuizStore`, `calculateResult`/`calculateParentResult`, `quiz/page.tsx`/`parent/quiz/page.tsx`가 거의 동일한 코드의 2벌이다. 여기에 3교시를 **복붙으로 추가하면 3벌이 되어** 이후 모든 변경 비용이 3배가 된다. 3교시 개발 전에 **퀴즈셋 레지스트리로 1회 리팩터링**하는 것을 전제로 한다.

## 4. 기능 상세 기획

### F1. 익명 집계 백엔드 + 상위 X% ⭐ 최우선

**왜**: "9등급"은 자조 개그지만, **"상위 3%"는 자랑**이다. 자랑이 스크린샷을 만들고, 스크린샷이 유입을 만든다. 사회적 증거는 동시에 신뢰도(이 서비스 많이 쓰는구나)도 준다.

**무엇을**
- 결과 화면 상단: `당신은 전체 응시자 34,182명 중 **상위 3.2%** 입니다`
- 유형 분포 바: `당신과 같은 유형 12.4% · 가장 흔한 유형은 K-장녀(21%)`
- 랜딩: `지금까지 34,182명 응시 · 오늘 1,204명` (실시간감 = 참여 압력)
- 유형별 랜딩 `/result/[type]`: 해당 유형 비율 표시 → **SEO 페이지에 고유 데이터가 생겨 색인 품질 상승**

**어떻게 (기술)**
- 테이블 `hyo_quiz_results` — 마이그레이션 `supabase/migrations/008_hyo_quiz_results.sql`

```sql
create table hyo_quiz_results (
  id           bigserial primary key,
  mode         text not null check (mode in ('child','parent','holiday')),
  result_id    text not null,
  grade        smallint not null,
  total_score  smallint not null,          -- 정규화 합산 0~300
  s_interest   smallint not null,          -- 0~100
  s_intimacy   smallint not null,
  s_expression smallint not null,
  entry        text,                       -- 'direct' | 'shared' | 'vs'
  hop_depth    smallint default 1,
  created_at   timestamptz default now()
);
create index on hyo_quiz_results (mode, created_at desc);
create index on hyo_quiz_results (mode, total_score);
alter table hyo_quiz_results enable row level security;  -- 클라이언트 직접 접근 전면 차단
```

- 쓰기: `POST /api/results` (Node 런타임, `createServerClient()` 서비스 롤)
- 읽기: `GET /api/stats?mode=child` → `{ total, today, percentileTable, typeDistribution }`, **`revalidate: 300`** 으로 캐싱(퍼센타일을 매 요청 계산하지 않는다)
- 퍼센타일은 5점 버킷 히스토그램을 5분마다 갱신해 O(1) 조회

**개인정보 가드레일 (반드시 지킬 것)**
- 🚫 **부모님 생년월일(`birthdays`)은 절대 서버로 보내지 않는다.** 현재도 클라이언트에만 있으며, 이는 개인정보다. 전송 금지를 코드 리뷰 체크리스트에 명시.
- 🚫 이름(`pname`), 개별 답변 배열도 전송하지 않는다. **결과 유형·환산 점수·유입 경로만** 보낸다.
- 어뷰징 대비: `ip_hash = sha256(ip + 일일 로테이션 솔트)` 로 일 단위 레이트리밋. **원본 IP는 저장하지 않고, 해시는 24시간 후 폐기.**

**정책 문구 개정 (필수 동반 작업)**
- `app/privacy/page.tsx`: "모든 답변 데이터는 결과 산출 후 즉시 휘발" → **"개인을 식별할 수 없는 결과 유형·점수 통계만 익명으로 집계하며, 입력하신 부모님 생년월일 등 개인정보는 서버로 전송되지 않고 브라우저에만 보관됩니다"**
- `app/page.tsx`의 FAQ 스키마 3번 항목도 동일하게 수정 (구글이 색인한 문구와 실제 동작이 달라지면 신뢰 이슈)

### F2. 맞대결 부메랑 루프 ⭐ 최우선

**왜**: 1홉 → 2홉을 만드는 유일한 장치. 기존 부모편 비교(`?parent=`)의 성공 패턴을 **모든 관계로 일반화**한다.

**무엇을**
1. 공유 URL을 `?vs=` 스키마로 일반화 (기존 `?parent=` 는 하위호환 유지)
   `/quiz?vs=FINANCIAL&vi=..&vn=..&ve=..&vname=..&vmode=child&d=1`
2. B가 응시를 마치면 결과 화면 최상단에 **대결 카드**: `민수 4등급 vs 나 6등급 — 내가 졌다`
   → 이미 있는 `MiniBar` 비교 컴포넌트 재사용
3. **"결과 돌려주기" 버튼** — B가 A에게 맞대결 결과를 카톡으로 회신. A가 앱으로 복귀(재방문 +) 하고, A는 다시 다른 사람에게 공유(3홉 +)
4. 공유 문구를 **도발형**으로: `나 4등급 나왔는데 너는? 자신 있으면 눌러봐 🌸` (현재는 서술형이라 클릭 동기가 약함)

**어떻게**
- `hooks/useKakaoShare.ts` 에 `vs` 파라미터 생성 로직 추가
- `hop_depth`: 공유 URL의 `d` 값을 +1 해서 다음 공유 URL에 실음. 결과 저장 시 함께 기록 → **백엔드 없이도 홉 깊이 측정 가능**
- `?s=<8자리 랜덤>` 공유 세션 ID: 동일 공유 링크의 열람 수 = 증폭률 측정 (개인 식별 아님)

### F3. 3교시 — 명절 생존력 시험 ⭐ 시즌 콘텐츠

**왜**: 기존 사용자에게 "새로 풀 것"을 주고(재방문), 추석 검색 수요를 직접 받는다(신규). 기존 엔진 재사용으로 개발비가 가장 싸다.

**선행 리팩터링 (필수)**
`packages/utils/src/quizSets.ts` 신설 — 퀴즈셋을 데이터로 등록:
```ts
export const QUIZ_SETS = {
  child:   { questions: QUESTIONS,        results: RESULTS,        ranges: CHILD_SCORE_RANGES,   axes: [...] },
  parent:  { questions: PARENT_QUESTIONS, results: PARENT_RESULTS, ranges: PARENT_SCORE_RANGES,  axes: [...] },
  holiday: { questions: HOLIDAY_QUESTIONS,results: HOLIDAY_RESULTS,ranges: HOLIDAY_SCORE_RANGES, axes: [...] },
}
```
- `useQuizStore`를 `createQuizStore(setId)` 팩토리로 통합
- `app/q/[set]/page.tsx` 단일 라우트로 통합, 기존 `/quiz`·`/parent/quiz` 는 리다이렉트 유지(SEO 보존)
- 예상 공수 1.5일. 이걸 안 하면 이후 모든 퀴즈 변경이 3배 비용

**콘텐츠 설계**
- 제목: **제3교시 · 명절 생존 탐구영역**
- 문항 12개 / 3축 재정의: **눈치(sense) · 노동(labor) · 방어력(defense)**
- 예시 문항: 잔소리 대응, 차례상 노동 분담, 용돈 전략, 친척 응대, 귀성길 운전, 사촌 비교당하기
- 결과 유형 8종 (예): `잔소리 방탄소년`, `주방 강제징집병`, `눈치 9단 스나이퍼`, `현금살포 전략가`, `귀성길 도망자`, `친척 인싸`, `방구석 잠수함`, `명절 마스터`
- **리스크 관리**: 며느리/사위 관련 문항은 성별 고정관념 이슈가 크다. **성별 중립 표현**을 기본으로 하고, 특정 성역할을 전제하는 선택지는 넣지 않는다. 자조 개그는 유지하되 **누군가를 조롱하는 방향은 배제**한다.
- 크로스 링크: 1교시 결과 → "3교시도 보러 가기", 3교시 결과 → "1교시 성적표 받기" (세션당 페이지뷰 = AdSense 수익 직결)

### F4. 세로형 결과 카드 이미지

**왜**: 현재 공유는 카카오 링크 중심(1200×630 가로 OG)이다. 인스타 스토리·스레드는 **9:16 세로**가 필수인데 대응이 없어 채널이 카톡 하나로 묶여 있다.

**무엇을**
- `/api/og?...&format=card` → **1080×1350 (4:5)** 세로 카드 생성
- 카드 구성: 등급 도장 + 유형명 + 한 줄 요약 + **상위 X%** + 3축 미니바 + QR 또는 짧은 도메인
- 결과 화면에 **"결과 이미지 저장"** 버튼: 같은 오리진이므로 `<a download href="/api/og?...">` 로 바로 저장 가능
- `share_image_saved` 이벤트 계측

**어떻게**: 기존 `app/api/og/route.tsx` 에 `format` 분기 + `ImageResponse`의 `width/height` 만 바꾸면 되므로 공수 0.5일. **폰트 서브셋 문자열(`OG_STATIC_TEXT`)에 새로 추가되는 고정 문구를 반드시 포함**시켜야 글자가 깨지지 않는다.

## 9. 결정 필요한 오픈 이슈

1. **3교시 문항 작성 주체** — 톤이 서비스 성패를 가른다. 직접 쓸지 / 초안을 받고 다듬을지?
2. **"상위 X%" 초기 표시 정책** — 데이터가 쌓이기 전(응시 1,000건 미만) 퍼센타일은 부정확하다. ⓐ 1,000건까지 숨김 ⓑ 시드 데이터 없이 "n명 중" 만 노출 — **ⓑ 권장** (거짓 숫자를 만들지 않는다)
3. **도메인 단축** — 세로 카드 QR/문구용 짧은 주소가 필요한가? (`hyodo-tier.yeomniverse.com`은 카드에 넣기엔 길다)
4. **커뮤니티 시딩 계획** — 추석 D-7에 어디에 뿌릴지 (에브리타임/블라인드/스레드/네이버 카페). 이건 개발이 아니라 운영 액션이라 별도 준비 필요.
5. **광고 배치** — 세션당 페이지뷰가 늘면 AdSense 수익이 오르지만, 결과 화면 광고는 공유 전환을 깎는다. **결과 화면 상단부는 광고 없이 유지**할 것을 권장.
